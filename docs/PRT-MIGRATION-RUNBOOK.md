## What 019 changes, in one paragraph

`accept_quote_create` and `accept_quote_edit` are replaced IN PLACE (identical
signatures — no PostgreSQL overload; ACLs, ownership, SECURITY DEFINER and
search_path preserved and verified) with the migration-018 bodies plus the
PR-T pickup guard, and one helper is added:
`public.linkmia_pickup_is_future(TIMESTAMPTZ, TIMESTAMPTZ)` — `LANGUAGE sql
IMMUTABLE STRICT`, security invoker, owned by the captured writer owner,
EXECUTE revoked from PUBLIC, anon, authenticated and service_role. After it
runs, every genuinely NEW write requires the submitted (create) or resolved
proposed (edit) pickup instant to be strictly later than the database clock:
once before mutation on `transaction_timestamp()`, and again as the LAST
potentially blocking statement of the inner subtransaction on
`clock_timestamp()` (SQLSTATE `ZQ019` → booking, acceptance, receipt AND
telemetry roll back → outcome `pickup_time_elapsed`). Receipt-first replay is
untouched: an exact retry lands on its receipt before any clock is read. No
table, column, index, constraint, trigger or RLS change, and NO grant change to
the existing writers (identity/owner/ACL/config verified equal to the
pre-capture). The one ACL event is the NEW helper, which gets a RESTRICTED ACL:
EXECUTE for the captured writer owner(s) only — PUBLIC, anon, authenticated,
service_role and every other grantee revoked, the exact set verified. The
`quote_verifications` verdict CHECK is untouched (the guard writes no verdict
row; the edit writer's pre-existing operationId-less `no_request_id`
instrument is unchanged and pinned — see Known residuals); no minimum lead
time; fares, tokens, cancellation and driver-status semantics unchanged;
`accept_optional_edit` untouched.

The artifacts are GENERATED by `database/migrations/tools/prt-guard-transform.js`
and must never be hand-edited: `node database/migrations/tools/prt-guard-transform.js --check`
and `tests/prt-pickup-integrity.test.js` assert byte-equality, and the same
check verifies the generated preflight fingerprints and the checksum table
below.

## Ordering relative to the code deploy — CODE FIRST, then SQL

The PR-T code (endpoint mapping `pickup_time_elapsed` → definitive HTTP 400,
the quote endpoint's staged strict-future gates, the create-side passenger
message, cache rung `linkmia-v1.3.28` / `linkmia-runtime-v5`) is deployed and
verified BEFORE the migration:

- code first, SQL later: the old writers never return `pickup_time_elapsed`,
  so the new mapping is inert until 019 installs; the quote endpoint's gates
  already refuse elapsed intents on the server clock; nothing breaks.
- SQL first, code later is FORBIDDEN: an old handler would map the new
  outcome through `unknownOutcomeResponse` as a sanitized 500 — a real
  refusal presented as an outage.

Between the code deploy and the migration a phase-bounded PR-T pre-migration
code rollback rung (29/6) existed: a code revert commit taking that fresh
pair. It was RETIRED UNUSED once migration 019 was verified on 2026-09-09 —
from here, removing the endpoint mapping, the passenger handling or the
helper dependency while guard-carrying writers are live is a separately
designed coordinated SQL-and-code decision.

## Known residuals (recorded 2026-09-09, accepted for this release)

- **Old-tab raw token, one session.** A booking page cached under the
  previous worker (`linkmia-v1.3.27`) keeps its generic quote-error branch
  until the `v1.3.28` worker activates on the following page load. The new quote
  endpoint answers an elapsed pickup with `{ error: 'pickup_time_elapsed',
  message }`, and that older page renders the `error` token verbatim in the
  quote card — where the previous endpoint sent the sentence "pickupAt is in
  the past" for pickups more than five minutes past (and still quoted the
  ±5-minute window). One-release transition residual; no data or money
  effect; clears on reload.
- **operationId-less edit telemetry (pinned, not moved).** In
  `accept_quote_edit` the inherited 017 `no_request_id` telemetry INSERT for
  a caller with no operationId (off/observe only) runs BEFORE the pre-guard
  and outside the subtransaction, so such a caller's elapsed refusal — or a
  final-guard crossing — leaves exactly that one telemetry row (no booking,
  acceptance or receipt). The create writer's counterpart sits inside the
  guarded block and leaves nothing. The browser always sends an operationId.
  `tests/prt-pickup-integrity.test.js` pins the positions in both artifacts
  and executes the lane in off and observe; moving the insert is a separate,
  deliberate 017-instrument decision.

## What this runbook does NOT cover

- Any change to fares, tokens, TTLs, cancellation, driver statuses, or a
  minimum lead time — none exists and none is introduced.
- The parked PR-B review card: it releases AFTER this migration is verified,
  under its own authorization, on its own rung (`v1.3.30`/`v7`).
- Historical rows: an already-stored elapsed pickup is not rewritten; it is
  refused only when a NEW write proposes an elapsed instant, and a pending
  ride whose old time passed can be rescued by submitting a future time.
